SRv6 WAN core lab — topology

Four VyOS PEs (one per data centre) dual-homed to a VyOS P-router triangle; IS-IS level-2 IPv6-only underlay carrying the SRv6 locators; BGP VPNv4 over SRv6 (End.DT4) reflected by p1; a VyOS CE per data centre speaking eBGP into VRF tenant-a; a CirrOS host behind each CE. 15 VMs on one libvirt/KVM host, ≈12 GiB RAM. core link (IPv6 /64, IS-IS, SRv6)access link (IPv4)

Links: core fd00:b:0:<ab>::/64 (first end ::1), PE–CE 172.16.n.0/30 (PE .1), CE–host 172.20.n.0/24 (CE .1 = gateway). OOB network srv6-oob 10.3.0.0/24 (host 10.3.0.1), consoles 127.0.0.1:5301–5315. VRF tenant-a: table 100, RT 65000:100, RD 65000:<pe#>.

Packet walk: h1 → h3 (dc1 → dc3)

  1. h1 172.20.1.2 sends to 172.20.3.2 via its gateway ce1 (172.20.1.1).
  2. ce1 has 172.20.3.0/24 from pe1 over eBGP → forwards to pe1 172.16.1.1 (VRF tenant-a).
  3. pe1: VRF route 172.20.3.0/24 = encap seg6 segs 1 [ fd00:c:3:0:X:: ] — the End.DT4 SID pe3 exported with the VPNv4 route (RD 65000:3, RT 65000:100, next hop fd00:a::3) via the route reflector p1. Outer IPv6 fd00:a::1 → fd00:c:3:0:X:: + SRH.
  4. p2 (the only shortest path west→east) forwards plain IPv6 towards pe3's locator fd00:c:3::/64 learned from IS-IS — no VRF, no IPv4 knowledge.
  5. pe3: local SID seg6local End.DT4 vrftable tenant-a decapsulates and looks the inner packet up in the VRF → ce3 172.16.3.2 → h3.
  6. Reply mirrors the path with pe1's SID. Forwarded packets need the locator block leaked into the VRF table (static route6 fd00:c::/40 … vrf default) because Linux scopes the encapsulation's outer lookup to the ingress VRF.
